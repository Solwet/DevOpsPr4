# Сравнение Cron и Systemd

| Критерий                     | **Cron**                                            | **systemd Timers**                                     |
|-----------------------------|-----------------------------------------------------|--------------------------------------------------------|
| **Архитектура**             | Отдельный демон (`crond`)                           | Встроен в `systemd` (единая система управления)        |
| **Минимальный интервал**    | 1 минута                                            | Микросекунды (при `AccuracySec=1us`)                   |
| **Логирование**             | По умолчанию — email; для файлов — нужно настраивать| Встроено через `journald` (просмотр через `journalctl`)|
| **Зависимости**             | Нет встроенной поддержки зависимостей               | Поддержка зависимостей (`After`, `Wants`, `Requires`)  |
| **Пропущенные запуски**     | Не обрабатываются (если система выключена — задача не выполнится) | При `Persistent=true` — компенсируются после включения |
| **Точность времени**        | Зависит от системного времени                       | Поддержка как монотонных (`OnBootSec`), так и календарных (`OnCalendar`) таймеров |
| **Гибкость расписания**     | Только календарное (5 полей)                        | И календарное (`OnCalendar`), и относительное (`OnBootSec`, `OnUnitActiveSec` и др.) |
| **Управление ресурсами**    | Нет                                                 | Можно ограничивать CPU, память и др. через `systemd`   |
| **Перезапуск при падении**  | Нет                                                 | Сервис можно настроить с `Restart=on-failure` и т.п.   |
| **Сложность настройки**     | Простая и привычная                                 | Требует понимания unit-файлов и структуры `systemd`    |
| **Портативность**           | Работает почти во всех Unix-системах                | Только в системах с `systemd` (современные дистрибутивы Linux) |
